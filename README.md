# 舞台色片叠放预检台

一个纯前端小工具：灯光师先设定六位十六进制的入射光源（默认白光，可切换有色 LED），再从色片目录拖入 **1–5 张** sRGB 色片、拖动调整实际叠放顺序，在装台前查看最终颜色、综合透光率以及“可用 / 过暗”结论。方案只保存在浏览器 `localStorage`，没有后端。

## 功能

- 入射光源可配置：六位十六进制 sRGB 颜色，默认白光 `#FFFFFF`，一键恢复白光。
- 内置色片目录，并支持录入名称、六位十六进制 sRGB 颜色、1–100 的整数透光率。
- 鼠标/触摸指针拖拽：目录 → 预检台，以及预检台内部调整顺序。
- 显示光源侧到输出侧的实际叠放顺序。
- 光源与色片按指定 sRGB 线性化公式逐通道相乘，再转回 sRGB 并四舍五入为整数。
- 综合透光率只由色片决定，按各层百分比相乘，四舍五入到 `0.1%`，不随光源变化。
- 综合透光率不低于 `20.0%` 标为 **可用**，否则标为 **过暗**。
- 结果区提供“逐层光路”明细（默认收起）：展开后从当前光源开始，按实际光路逐张列出经过每层后的累计色块、RGB、累计透光率和明暗结论；末行与预检总结果完全一致，拖动换序、增删色片或修改光源后两处同步重算。空预检台不显示该入口。
- 非法六位十六进制颜色（色片或光源）会在对应输入处明确报错；光源非法时计算与本地记录沿用上一次有效颜色，且不会写入或覆盖最近一次有效方案。
- 刷新后自动从 `localStorage` 恢复最近一次有效方案（1–5 张；每层必须有非空标识和名称，颜色和透光率均有效）及其自定义光源。
- “设为基准”把当前方案连同当时的光源颜色固化为基准快照，继续修改光源或一至五层色片即可实时对比：基准与当前色块并列展示，颜色差按 sRGB 转 CIE Lab 后计算 Delta E 76，亮度差取两方案综合透光率的绝对百分点；颜色差不超过 `8` 且亮度差不超过 `5.0` 个百分点判为 **可替代**，否则标为 **偏差明显**。“清除基准”回到单方案流程。空方案不能设为基准，也不会改写已有基准；基准快照随最近有效方案一并存入 `localStorage`，刷新时会依据基准层及其光源重新计算结果，损坏、越界或层内容与结果矛盾的基准只被忽略，不影响方案恢复。

## 计算规则

### 1. sRGB 转线性

对每个通道值 `v8`（0–255）：

```text
v = v8 / 255
当 v <= 0.04045：L = v / 12.92
否则：          L = ((v + 0.055) / 1.055) ^ 2.4
```

### 2. 光源与多层叠色

光源颜色先按同一公式线性化，再与各层色片对红、绿、蓝三个通道分别相乘：

```text
Lout(c) = Llight(c) × L1(c) × L2(c) × … × Ln(c)
```

省略光源时按白光 `#FFFFFF` 处理，与旧版固定白光行为完全一致。

### 3. 线性转回 sRGB

```text
当 Lout <= 0.0031308：S = 12.92 × Lout
否则：                S = 1.055 × Lout^(1 / 2.4) - 0.055

输出通道 = Math.round(S × 255)
```

输出结果会限制在 0–1 后再转换，保证通道整数在 0–255 内。

### 4. 透光率

```text
综合透光率(%) = roundTo0.1(T1 × T2 × … × Tn)
```

颜色本身表示该色片允许通过的光谱比例；输入的透光率是整体光通量比例，因此颜色通道与透光率分开计算并展示。光源只参与颜色通道计算，透光率仍只由色片决定。

## 一组可复算示例

### 示例 A：正红 + 火焰橙

按顺序叠放：

1. 正红 R02：`#D82128`，72%
2. 火焰橙 O15：`#F26322`，68%

最终颜色：

```text
#CD0601
R 205 / G 6 / B 1
```

综合透光率：

```text
72% × 68% = 48.96% → 49.0%
```

结论：**可用**（49.0% ≥ 20.0%）。

> 颜色乘法在线性空间中是可交换的，所以只改两张色片顺序不会改变最终颜色；但界面仍保留真实叠放次序，供三至五张不同滤镜和现场记录使用。

### 示例 B：20.0% 判定边界

两张透光率分别为 21% 和 95%：

```text
21% × 95% = 19.95% → 20.0%
```

结论：**可用**。判定使用四舍五入后的 `20.0%`。

### 示例 C：明确过暗

三层透光率为 60%、40%、80%：

```text
60% × 40% × 80% = 19.2%
```

最终颜色（若三层都是 `#FFFFFF`）仍为白色，但光通量结论为：**过暗**。

### 示例 D：五张内置深色片

按顺序叠放：

1. 皇紫 V58：`#603E96`，42%
2. 海蓝 B46：`#1377BE`，52%
3. 叶绿 G38：`#1F9D4D`，56%
4. 玫瑰品红 M67：`#C13B8F`，48%
5. 青蓝 C72：`#12A8B5`，61%

综合透光率：

```text
42% × 52% × 56% × 48% × 61% = 3.5819...% → 3.6%
```

最终颜色：`#000005`（R 0 / G 0 / B 5）。

结论：**过暗**。

### 示例 E：冷色 LED 光源

光源 `#A0C8FF`，按顺序叠放：

1. 正红 R02：`#D82128`，72%
2. 火焰橙 O15：`#F26322`，68%

最终颜色：

```text
#800401
R 128 / G 4 / B 1
```

综合透光率仍为 `49.0%`（只由色片决定），结论：**可用**。

白光下同一叠放结果为 `#CD0601`；两结果的颜色差 Delta E 76 约为 `32.4`，因此白光基准下仅切换该光源即判为 **偏差明显**。

## 测试

### Vitest：计算边界与存储保护

```bash
npm run test:unit
```

覆盖内容包括：

- `0.04045` 分段边界和 sRGB 往返；
- 非法六位颜色、非整数/越界透光率；
- 1–5 张数量限制；
- 通道四舍五入；
- 透光率相乘、保留 0.1%、20.0% 边界；
- 缺省光源与白光等价、有色光源固定样例、透光率不随光源变化；
- 非法或空方案不覆盖最近一次有效方案；
- sRGB → CIE Lab 固定颜色锚点、Delta E 76 阈值两侧、基准快照的新旧存储结构兼容；
- 光源字段的写入、恢复与缺省白光兼容，基准按其自身光源校验结果一致性；
- 逐层光路：两层固定样例验证首层（仅经过一张色片）、末层（等同总结果）与换序后的累计契约，累计透光率逐层相乘并逐层给出明暗结论。

### Playwright：拖拽、错误和刷新恢复

首次运行需安装浏览器：

```bash
npx playwright install chromium
npx playwright install-deps chromium  # 需要系统包管理权限
```

运行：

```bash
npm run e2e
```

E2E 覆盖：

1. 从目录拖入两张色片；
2. 在叠放区拖动改变顺序；
3. 校验最终颜色、RGB、透光率与结论；
4. 刷新后恢复顺序和结果；
5. 非法六位颜色显示错误，且 `localStorage` 中有效方案不被覆盖；
6. 超过五张时拒绝加入；
7. 五张低透光率色片显示“过暗”；
8. 建立基准、替换一层得到“可替代”结论、刷新后恢复对比；
9. 空方案不能设为基准，清除基准后回到单方案流程；
10. 切换有色光源后重算最终颜色，透光率不变，刷新后恢复自定义光源；
11. 白光下建立基准后仅改变光源，两项差值与替代结论随之更新，刷新后对比仍在；
12. 非法光源在输入处报错、结果不跳变，刷新恢复最后有效方案，恢复白光后立即重算并保存；
13. “逐层光路”默认收起、空预检台无入口；展开后首层/末层数值正确，拖动换序后检查点顺序与数值同步，修改光源后逐层重算；
14. 刷新后按现有记录恢复方案与光源并重新生成检查点、明细保持收起，且存储中没有新增字段；非法光源期间已展开的明细保持最后有效结果。

一次性运行全部检查：

```bash
npm run verify
```

## Docker Compose

```bash
docker compose up --build web
```

```bash
WEB_PORT=3000 docker compose up --build web
```

```bash
docker compose run --build --rm verify
```

## localStorage 数据格式

键名：

```text
stage-gel-precheck:latest-scheme:v1
```

示例：

```json
{
  "version": 1,
  "savedAt": "2026-09-11T10:00:00.000Z",
  "lightSource": "#A0C8FF",
  "layers": [
    {
      "id": "primary-red",
      "name": "正红 R02",
      "hex": "#D82128",
      "transmittance": 72
    }
  ],
  "baseline": {
    "savedAt": "2026-09-11T09:30:00.000Z",
    "lightSource": "#FFFFFF",
    "layers": [
      {
        "id": "primary-red",
        "name": "正红 R02",
        "hex": "#D82128",
        "transmittance": 72
      }
    ],
    "result": {
      "hex": "#D82128",
      "rgb": [216, 33, 40],
      "transmittancePercent": 72,
      "conclusion": "可用"
    }
  }
}
```

读取时会重新校验：必须是版本 1、一至五层、每层都有非空标识和名称，颜色是合法六位十六进制值，透光率是 1–100 的整数。损坏数据不会被恢复，也不会主动覆盖存储中已有内容。`lightSource` 为可选字段：旧记录没有该字段时按白光 `#FFFFFF` 处理；字段本身非法时仅忽略该字段、按白光恢复，方案照常还原。`baseline` 为可选字段：仅含 `layers` 的旧数据按无基准处理；基准可以携带自己的 `lightSource`（同样缺省按白光），基准本身损坏、越界，或其 `result` 与根据基准层和基准光源重新计算出的结果不一致时，只忽略基准，当前方案照常恢复。

“逐层光路”明细完全由当前有效光源与色片层派生：不写入任何新的存储字段，展开/收起状态也不持久化；刷新后先按上述方案恢复，再用同一套线性叠色与透光率规则重新生成检查点。旧记录、基准快照、五层上限与基准比较结果均不受影响。
