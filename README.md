# 舞台色片叠放预检台

一个纯前端小工具：灯光师可从色片目录拖入 **1–5 张** sRGB 色片、拖动调整实际叠放顺序，在装台前查看最终颜色、综合透光率以及“可用 / 过暗”结论。方案只保存在浏览器 `localStorage`，没有后端。

## 功能

- 内置色片目录，并支持录入名称、六位十六进制 sRGB 颜色、1–100 的整数透光率。
- 鼠标/触摸指针拖拽：目录 → 预检台，以及预检台内部调整顺序。
- 显示光源侧到输出侧的实际叠放顺序。
- 按指定 sRGB 线性化公式逐通道相乘，再转回 sRGB 并四舍五入为整数。
- 综合透光率按各层百分比相乘，四舍五入到 `0.1%`。
- 综合透光率不低于 `20.0%` 标为 **可用**，否则标为 **过暗**。
- 非法六位十六进制颜色会在表单处明确报错，且不会写入或覆盖最近一次有效方案。
- 刷新后自动从 `localStorage` 恢复最近一次有效方案（1–5 张、颜色和透光率均有效）。
- “设为基准”把当前方案固化为基准快照，继续编辑一至五层即可实时对比：基准与当前色块并列展示，颜色差按 sRGB 转 CIE Lab 后计算 Delta E 76，亮度差取两方案综合透光率的绝对百分点；颜色差不超过 `8` 且亮度差不超过 `5.0` 个百分点判为 **可替代**，否则标为 **偏差明显**。“清除基准”回到单方案流程。空方案不能设为基准，也不会改写已有基准；基准快照随最近有效方案一并存入 `localStorage`，损坏或越界的基准只被忽略，不影响方案恢复。

## 计算规则

### 1. sRGB 转线性

对每个通道值 `v8`（0–255）：

```text
v = v8 / 255
当 v <= 0.04045：L = v / 12.92
否则：          L = ((v + 0.055) / 1.055) ^ 2.4
```

### 2. 多层叠色

对红、绿、蓝三个通道分别相乘：

```text
Lout(c) = L1(c) × L2(c) × … × Ln(c)
```

### 3. 线性转回 sRGB

```text
当 Lout <= 0.0031308：S = 12.92 × Lout
否则：                S = 1.055 × Lout^(1 / 2.4) - 0.055

输出通道 = Math.round(S × 255)
```

输出结果会限制在 0–1 后再转换，保证通道整数在 0–255 内。

### 4. 透光率

```text
综合透光率(%) = roundTo0.1(T1 × T2 × … × Tn)
```

颜色本身表示该色片允许通过的光谱比例；输入的透光率是整体光通量比例，因此颜色通道与透光率分开计算并展示。

## 一组可复算示例

### 示例 A：正红 + 火焰橙

按顺序叠放：

1. 正红 R02：`#D82128`，72%
2. 火焰橙 O15：`#F26322`，68%

最终颜色：

```text
#CD0601
R 205 / G 6 / B 1
```

综合透光率：

```text
72% × 68% = 48.96% → 49.0%
```

结论：**可用**（49.0% ≥ 20.0%）。

> 颜色乘法在线性空间中是可交换的，所以只改两张色片顺序不会改变最终颜色；但界面仍保留真实叠放次序，供三至五张不同滤镜和现场记录使用。

### 示例 B：20.0% 判定边界

两张透光率分别为 21% 和 95%：

```text
21% × 95% = 19.95% → 20.0%
```

结论：**可用**。判定使用四舍五入后的 `20.0%`。

### 示例 C：明确过暗

三层透光率为 60%、40%、80%：

```text
60% × 40% × 80% = 19.2%
```

最终颜色（若三层都是 `#FFFFFF`）仍为白色，但光通量结论为：**过暗**。

### 示例 D：五张内置深色片

按顺序叠放：

1. 皇紫 V58：`#603E96`，42%
2. 海蓝 B46：`#1377BE`，52%
3. 叶绿 G38：`#1F9D4D`，56%
4. 玫瑰品红 M67：`#C13B8F`，48%
5. 青蓝 C72：`#12A8B5`，61%

综合透光率：

```text
42% × 52% × 56% × 48% × 61% = 3.5819...% → 3.6%
```

最终颜色：`#000005`（R 0 / G 0 / B 5）。

结论：**过暗**。

## 本地开发

要求 Node.js 20+。

```bash
npm install
npm run dev
```

生产构建：

```bash
npm run build
npm run preview
```

## 测试

### Vitest：计算边界与存储保护

```bash
npm run test:unit
```

覆盖内容包括：

- `0.04045` 分段边界和 sRGB 往返；
- 非法六位颜色、非整数/越界透光率；
- 1–5 张数量限制；
- 通道四舍五入；
- 透光率相乘、保留 0.1%、20.0% 边界；
- 非法或空方案不覆盖最近一次有效方案；
- sRGB → CIE Lab 固定颜色锚点、Delta E 76 阈值两侧、基准快照的新旧存储结构兼容。

### Playwright：拖拽、错误和刷新恢复

首次运行需安装浏览器：

```bash
npx playwright install chromium
npx playwright install-deps chromium  # 需要系统包管理权限
```

运行：

```bash
npm run e2e
```

E2E 覆盖：

1. 从目录拖入两张色片；
2. 在叠放区拖动改变顺序；
3. 校验最终颜色、RGB、透光率与结论；
4. 刷新后恢复顺序和结果；
5. 非法六位颜色显示错误，且 `localStorage` 中有效方案不被覆盖；
6. 超过五张时拒绝加入；
7. 五张低透光率色片显示“过暗”；
8. 建立基准、替换一层得到“可替代”结论、刷新后恢复对比；
9. 空方案不能设为基准，清除基准后回到单方案流程。

一次性运行全部检查：

```bash
npm run verify
```

## Docker Compose

启动 Web 服务：

```bash
docker compose up --build web
```

默认映射到宿主机 `8080` 端口：<http://localhost:8080>

用 `WEB_PORT` 覆盖宿主端口：

```bash
WEB_PORT=3000 docker compose up --build web
```

运行一次性验证服务（Vitest + Playwright，容器退出即结束）：

```bash
docker compose run --build --rm verify
```

`verify` 服务会等待 `web` 健康后，通过 `BASE_URL=http://web/` 访问容器内站点。

## localStorage 数据格式

键名：

```text
stage-gel-precheck:latest-scheme:v1
```

示例：

```json
{
  "version": 1,
  "savedAt": "2026-09-11T10:00:00.000Z",
  "layers": [
    {
      "id": "primary-red",
      "name": "正红 R02",
      "hex": "#D82128",
      "transmittance": 72
    }
  ],
  "baseline": {
    "savedAt": "2026-09-11T09:30:00.000Z",
    "layers": [
      {
        "id": "primary-red",
        "name": "正红 R02",
        "hex": "#D82128",
        "transmittance": 72
      }
    ],
    "result": {
      "hex": "#D82128",
      "rgb": [216, 33, 40],
      "transmittancePercent": 72,
      "conclusion": "可用"
    }
  }
}
```

读取时会重新校验：必须是版本 1、一至五层、每层颜色是合法六位十六进制值、透光率是 1–100 的整数。损坏数据不会被恢复，也不会主动覆盖存储中已有内容。`baseline` 为可选字段：仅含 `layers` 的旧数据按无基准处理；基准本身损坏或越界时只忽略基准，当前方案照常恢复。
